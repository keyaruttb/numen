# 表达策略层 V9.5（2026-11-20）

> 落地对象：`拟人化表达策略规范-SYNAPSE-1024-V1.0.md`（他 11-20 上午给我的那份）。
> 一句话：把「怎么说话」从人格锚里拆出来，做成**一层可热改、可回滚、缓存友好**的规则，
> 让她的表达不再只是「贴情绪标签的应答机」。

---

## 1. 它插在哪

```
人格锚 Persona   ── 我是谁、性格底色（identity 文档，不动）
    │
表达策略 Policy  ── 怎么说话、怎么接、分寸、边界（本次新增：speech_policy 表）
    │
当下状态 State   ── 心境 / PAD / 亲密度 / 态度（每轮变，仍在【此刻】）
```

上下文里的落位（`card2.assemble_context`）：

```
【我是谁】…          ← 稳定（缓存地基）
【说话方式】…        ← 稳定（本次新增，紧跟人格，每轮一字不变）
【我一直记得的事】…   ← 稳定
…【关联想起】【学过的】【印象】【态度】…
【此刻】…            ← 每轮变；末尾多一行「本轮分流」提示
```

缓存原则：稳定的在前、会动的在尾；【说话方式】若每轮变，前缀缓存就会从它开始断。

## 2. 存储（两张表，可热改可留痕）

```sql
CREATE TABLE speech_policy(
    key        TEXT PRIMARY KEY,   -- length/address/empathy/tempo/manner/boundary
    enabled    INTEGER DEFAULT 1,
    text       TEXT,               -- 给模型读的自然语言条文
    weight     REAL DEFAULT 0.8,   -- 0~1，调浓淡
    updated_ts REAL,
    version    INTEGER DEFAULT 1
);
CREATE TABLE speech_policy_log(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    key TEXT, old_text TEXT, new_text TEXT,
    enabled INTEGER, weight REAL,
    source TEXT,      -- console / manual / test …
    ts REAL, version INTEGER
);
```

代码：`D:\speech_policy.py`（`ensure / render / set_policy / listing / log / stats / round_mode / mode_hint`）。

- `render(conn)`：把 `enabled=1` 的条文按固定顺序拼成一段 → 每轮内容完全一样（可断言）。
- `set_policy(conn, key, text=, enabled=, weight=, source=)`：改一条、`version+1`、写 log。
- 默认 6 条（长度节奏 / 称谓自称 / 共情与分流 / 情绪外化 / 分寸互动 / 事实边界），共约 680 字。

## 3. 本轮分流（唯一的「每轮变」部分）

```python
round_mode(pad, query) -> "闲聊" | "办事" | "观望" | "绷躁"
```

- 判断顺序：PAD 里 `p < -0.12 且 a >= 0.15` → 绷躁；问句里有「帮我/怎么/步骤/查一下…」→ 办事；
  有「是不是/要不要/该不该/有点」→ 观望；其余 → 闲聊。
- 读出来的只是**一行提示**，追加进【此刻】：
  「这轮更像办事：先给能用的答案或下一步，语气放首尾。」
- 为什么放尾巴：它每轮会变，塞进稳定格就等于每轮都把缓存地基砸一次。

---

## 4. 与现有模块的挂钩

| 规范要求 | 本卡落法 |
| --- | --- |
| 接 Goal（闲聊/办事） | `round_mode()` 读本轮问句 + `motiv` 候选（预留 intentions 参数） |
| 接 Relationship（称谓/亲密度） | 称谓仍由 `identity` 里的规则管；亲密度低时的「收着点」由 `_affect_tone()` 给（V9.4 已上线） |
| 接当下状态（PAD） | `pad_style_hint()` 给状态句；策略层只规定「怎么表达这个状态」，不改数值 |
| 接边界（防编造） | `boundary` 条文 + `identity` 里原有三条底线（不装记得、不拿消失当筹码、不演别人） |
| 不写死台词 | 条文全是「倾向/分寸」，没有一句可直接照抄的台词 |
| 不动人格锚 | `speech_policy` 与 `identity` 分开存、分开改 |

## 5. 开关与调参

| 变量 / 键 | 作用 |
| --- | --- |
| `WHALE_SPEECH=0` | 整个【说话方式】格不注入（回退到旧行为） |
| `WHALE_SPEECH_MODE=0` | 不注入本轮分流那一行 |
| `WHALE_SPEECH_CHARS=700` | 稳定格的字数上限 |
| `speech_policy.weight` | 条文浓淡（0~1）；目前用于门槛过滤与排序，不做「自动改写语气」 |
| `speech_policy.enabled` | 单条关掉 |

## 6. 预算与让位（踩过的坑）

- 【说话方式】的字数**计入 `used`**，不白吃预算；
- 预算真爆（`len(text) > TOKEN_BUDGET`）时，整块摘掉【说话方式】——
  人格与证据优先于「怎么说话」的规则。`test_card2` 的「超大输入不崩」就是拿 5000 字人格压这一条。

## 8. 与那份规范相比，明确没做的

1. **称谓没有做成「亲密度驱动自动切换」**：现在还是 identity 里的固定规则 + `_affect_tone` 的分寸句。
2. **`weight` 没有做「浓淡改写」**：只是过滤门槛，不会把条文改写得强/弱。
3. **输出后自检（第 7 节红线清单）没有做成拦截**：目前是提示层约束，不是生成后再校验一遍。
4. **few-shot 对照评测没做**：第 8 节那六组样本还没跑「接入前/接入后」，因为改的是提示而非参数，肉眼对比不算证据。
5. **外部角色梗一律没引**：那份规范自己划的红线（不复制外形/偏好/专属梗），照做。

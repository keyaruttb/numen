## 3. 数据模型

一张卡 = 一个 SQLite。核心表（列只列关键项，完整 DDL 见各模块 `_DDL` 常量）：

**记忆本体**
```sql
mem(id, raw, verb, obj, w REAL, salience REAL, tier TEXT, erase_stage INT,
    dead INT, t_anchor REAL, region TEXT, speaker TEXT, ...)
chunk(id, mem_id, seq, text, ts, source, emb BLOB)          -- 768 维 float32 = 3072 字节
mem_birth(id, mem_id, ...)                                   -- 出生证：每条记忆的来源
synapse(a, b, kind, weight REAL, fire_count INT, last_touch)  -- kind ∈ semantic/time/co/tag
dialogue(id, who, text, ts, ...)
inbox(id, who, hat, state, due_ts, due, ...)
```

**印象与态度**
```sql
impression(id, subject, scene_mood, text, n INT, weight REAL, via TEXT, ...)  -- via ∈ direct/indirect
affect(id, target_kind, target_tag, valence, safety, expectation, salience,
       n_pos, n_neg, linked_mems, version, updated_ts)
facts(id, subject, predicate, object, status, updated_ts)    -- status ∈ active/superseded
```

**反馈与反思（v9.0–v9.3）**
```sql
feedback(id, kind, mem_id, dialogue_id, actor, ts_action, ts_settle, status,
         approval, correction, reject, confirm, confirm_weak, confirm_level,
         disconfirm, reuse, promise, severity, r, r_bucket, note, source, trust_ok, ts)
learn_eval(mem_id PK, value, times_used, times_confirmed, times_disconfirmed,
           confirm_strength, last_eval_ts, verdict)
review(id, mem_id, side, angle, summary, polished_summary, fb_ids, related_mems,
       evidence_n, evidence_strength, strength, promoted, confirmed, ts)
intention(id, fb_id, mem_id, direction, kind, drive, scene_tag, urge,
          decay_hl, status, note, created_ts, last_touch_ts)
gov_decision(id, ts, subject_kind, subject_id, action, reason, source, conflicts, applied, extra)
```

**运行时**
```sql
meta(key PK, val)          -- 激素、心境、调节器状态、所有可热改参数
timeline(seq, ts, kind, payload, prev_hash, hash)   -- 哈希链，证「身份没被改过」
recall_event(...)          -- 召回事件与结算
write_outbox(id, idem UNIQUE, kind, ref_id, payload, state, attempts, next_ts, last_error, ...)
speech_policy(key PK, enabled, text, weight, updated_ts, version)
speech_policy_log(id, key, old_text, new_text, old_enabled, new_enabled, old_weight, new_weight, source, ts, version)
learn_task(id, topic, why, source, prio, state, ...)
```

**评审可查的三件事**：① 每条记忆都有 `mem_birth`（来源可追）；② `timeline` 是前向哈希链（改历史会断链）；③ 派生数据（chunk / 边 / 印象）失败会进 `write_outbox`，不是静默丢。

## 4. 主链时序（真实函数名）

```python
# 一次对话（同步，全程持写锁）
with mind.lock:                          # writer_lease
    card.feedback.settle_from_reaction(user_message, now=ts)   # 1) 给「上一句」结账
    user_mid = card.remember(user_message, speaker="user", ...) # 2) 落他的话
    ctx      = card.assemble_context(user_message)              # 3) 组装 prompt
    #   ── 模型在外面生成回复 ──（本卡不调模型）
    reply_mid = card.remember(reply, speaker="self", ...)       # 4) 落我的话
    card.feedback_open("self_utterance", reply_mid, ...)        # 5) 挂一条待结算
```

要点：
- **先结账再落话**：他这句话是对我上一句的反应，所以结算必须发生在写新记忆之前，否则会拿错的账。
- `remember()` 在 `cardmix_store.py`，**不在** `card2.py`；四张表（mem/dialogue/inbox/mem_birth）同一事务。
- 派生索引（chunk/边/印象/facts/timeline）在同一事务完成后立刻做；任一步抛错 → `outbox.enqueue()`，由维护线程补。

**评审问题**：如果模型生成失败、只有 `user_message` 落卡，结算已经发生但 `self_utterance` 没挂上——下一句会把账结到更早的一条上。这是已知的顺序假设，见 §14-R3。

## 5. 召回与打分

### 5.1 三路候选

| 路 | 实现 | 过滤 |
|---|---|---|
| 精确字面 | `WHALE_EXACT=1` 默认开；字面命中直接加权 | 归一化后按 10 字窗 |
| 语义向量 | `semantic` 层（bge-base-zh-v1.5，768 维）+ 记忆级余弦 | 时间窗 + dead=0 + tier |
| 块检索 | `chunk_retriever`（同模型，块 120~240 字） | 同上 |

### 5.2 融合打分（生产值）

```python
s = SCORE_W[0]*blended_vec + SCORE_W[1]*cover + SCORE_W[2]*clarity + SCORE_W[3]*recency
SCORE_W = (0.35, 0.30, 0.00, 0.00)     # 实测：清晰度/新近是噪声 → 置 0
RECALL_NARROW_MAX = 13                  # 候选收窄到 13 条
```

证据格额外硬配额 `WHALE_EVID_QUOTA = 0.35`：证据类至少占 35% 预算，差额只从**人格/长期**挪，不从证据挪。

### 5.3 实测（可复现）

| 尺子 | 口径 | 数 |
|---|---|---|
| bench 417 题（虚拟时钟） | 全量命中 | **34.1%** |
| bench（同上） | 有证据轮 305 题 | **46.6%** → 加证据配额后 **47.2%** |
| 真卡 23 条（recall 8 / evidence 3 / attack 6 / normal 6） | top-3 已知答案 | R@1 **62.5%** / R@3 **75%** / 证据 **100%** |

> 注意口径：bench 是「任意一条证据出现」；真卡 23 条是「top-1 命中心仪答案」。两个数**不能相加也不能比较**，只能各自纵向看版本变化。

### 5.4 已被证伪的做法（写下来免得后人再试）

- **纯余弦权重** `(1.0, 0, 0, 0)`：bench 31.9%，真卡退化到 50/75/66.7 —— 不行。
- **多路并集 RRF**：候选天花板 81%，但端到端只 46.6%（+1 点在噪声内）→ 默认关。
- **块切分换 bge-base / 换窗口**：对结果无显著影响 → 不动。
- 旧 worklog 里记的 baseline 36.0% **不可复现**（bench 卡被改过），已废弃，不再引用。

## 6. 上下文装配（prompt 是怎么拼的）

格顺序（`assemble_context` 返回 `{"text", "sections", ...}`）：

```
【我是谁】人格整段（恒定，缓存地基）
【长期印象】【学过的】【联想】【期待】【欲望】【事实】
【印象】亲历 direct / 联想 indirect(×0.45)
【态度】per person / scene
【关联想起】来自 attitude.linked_mems（≤2 条、每条 80 字）
【翻旧账】【工作台】【此刻】心情 + PAD + 语气分寸
【说话方式】稳定格 9 条（≤800 字，独立配额）
【这一轮】分流标签 + 称谓距离
```

### 6.1 预算与让位（v9.6.1 / v9.6.2 修过一次真 bug）

- 四格预算来自 `runtime_config.BUDGET`，实际 `plan["total"] = 13500`。
- **让位闸**：超长时按「有多可惜」从低到高丢——
  `工作台 → 旧账 → 关联想起 → 期待 → 事实 → 欲望 → 这一轮 → 说话方式`；
  **人格 / 长期 / 证据 / 此刻永不在名单**。
- 外挂配额：`【说话方式】+【这一轮】` 共 `1200` 字（`WHALE_EXTRA_CHARS`），不计入四格，也不进让位名单（`=0` 回退旧行为）。

> 历史事故：让位闸原先按写死的 `TOKEN_BUDGET = 6000` 判断，而线上 prompt 本来就 6800~7000 字 → **每一轮都把策略格砍掉**，卡层测试却全绿（卡层 prompt 只有 3000~4000 字，永远碰不到闸）。教训：新模块上线必须看**线上真 prompt**，不能只看单测。

### 6.2 稳定格的缓存意义

【说话方式】两轮之间**一字不差**（实测 784 字），故意放在靠近顶部的位置，让上游 prompt cache 命中；每轮会变的内容（此刻 / 这一轮）放尾部。

## 7. 情绪与激素

### 7.1 三层结构

| 层 | 数量/形态 | 更新方式 |
|---|---|---|
| 内脏 `viscera` | 24 项（含血清素/多巴胺等 4 项核心的镜像） | 事件注入 + 每小时回归 |
| 核心 `hormone` | 4 项：sero / dopa / cort / oxy | 注入 + 稳态回归 + 软带 |
| 引擎 `synapse_emotion` | 五维状态 + TD 期望 `expect[scene]` | Appraisal 或 RPE 直注 |

### 7.2 基线（实测，`hormone.bases_at(None)`）

```
h_sero 0.66   h_dopa 0.48   h_cort 0.20   h_oxy 0.50
稳态回归 λ = 0.05/小时；软带 [0.15, 0.85] 之外只收 30%（所有注入路径都过）
```

### 7.3 RPE 与两条「不重复记账」的仓库

```python
# 结算给激素（viscera 口径，meta 的 h_*）
cand = hormone.apply_r(hs, r, scale=0.22, severity=sev)   # 正向抬 oxy/dopa/sero，负向抬 cort

# 结算给引擎（synapse_emotion 口径，qq_state/emotion/xiyin.json）
engine.inject_rpe(rpe=r/R_CAP, scenario=kind, intensity=1.0)  # 改 eng.st / expect，不碰 h_*
```

> 评审常见误解：这两处**不是**重复记账。前者改 24 项激素的 4 个核心项，后者改引擎内部状态与期望学习；两者物理上不同文件、不同字段。我在设计评审时曾误判为「结两次账」，后来读代码更正。

### 7.4 负反馈（v9.8，本次评审重点）

文档给的方案是**绝对阈值**（饱和 0.82 / 释放 0.60）。我实测基线后改了一处：

```
rel_eff = min(sat_th - 0.02, max(rel_th, base + rel_margin))   # rel_margin = 0.07
```

原因：血清素基线 0.66 > 释放线 0.60 → 一旦进抑制，激素落到 0.66 就停住，**永远回不到 0.60 以下，抑制永久卡死**。改后：血清素 0.82 触发、0.73 释放（滞回带 0.09）。

状态机：
```
level >= sat_th        → gain_mod → 降到 0.35，clear_mod = 1.45，报 HORMONE_SUPPRESS（仅进入时）
rel_eff <= level < sat → 维持（滞回，防抖）
level < rel_eff        → gain_mod 回 1.0，clear_mod = 1.0，报 HORMONE_RELIEVE
```
- `apply_gain(hs, cand, mods)`：只对**增量**乘增益，不重算 ETA（所以不会把基线一起缩放）。
- `regulated_regress`：清除系数进回归指数 `k = exp(-λ·clear_mod·dt)`。
- 状态持久化在 `meta.hf_state`，进程重启即恢复；参数走 `meta.hf_*`，`/hormone/feedback` 热改。

**实测（真卡副本，23/23 通过）**：进抑制 gain 0.9→0.35、clear 1.45；滞回带内不重复报；跌到 0.40 报 RELIEVE、gain 回升；血清素 `rel_eff=0.730`，0.72 能放出；`apply_gain` 增量折 35%（0.80→0.87）；连夸 15 句 dopa .990→.950、oxy .848→.871，不贴 1.0；跨 15 小时连夸被压回 .72~.78。

**线上（真卡）**：重启后 40 秒，`suppressed=['h_oxy','h_dopa','h_sero']`、gain 0.9949、三条 SUPPRESS 事件，`meta.hf_state` 已落。

**已知观察点**：oxy 阈值 0.82 偏低（依恋类激素容易被压制），可能要做成**分激素阈值**——见 §14-R1。

## 8. 反馈闭环（v9.0–v9.5）

### 8.1 奖励怎么算

```
r = 0.30·approval − 0.30·correction − 0.20·reject
  + 0.15·confirm + 0.05·confirm_weak − 0.15·disconfirm
  + 0.05·reuse + 0.05·promise                       （夹 ±0.5）

severity_alg = 0.35·correction + 0.30·reject + 0.20·disconfirm + 0.15·max(0,−promise)
               线性映射到 [0.35, 0.80]；负向幅度再乘 (0.6 + 0.4·severity)
```

阈值：`r > 0.15` 正、`r < −0.15` 负、之间中性（**中性不生意向**，否则旧事实被推翻会凭空长出「想躲」）。

### 8.2 七步结算

| 步 | 落地 | 关键参数 |
|---|---|---|
| ① 激素 | `hormone.apply_r` + 负反馈 `apply_gain` | scale 0.22 |
| ② 记忆 | 权重 / 显著度 | `MEM_W_STEP=0.04`、`MEM_SAL_STEP=0.05` |
| ②b 突触 | `synapse.reinforce` / `weaken(factor=0.5)` | 削弱不删边 |
| ③ 学习评价 | `learn_eval.value` | `LEARN_VALUE_STEP=0.10`；strong +1.0 / weak +0.4 / 推翻 −1.0 |
| ④ 印象 | `impression.observe(subject='self')` | — |
| ⑤ 动机 | `motiv.bump` / `motiv.itch` | `MOTIV_STEP=0.10` |
| ⑥ 意向 | `intention` 表 | 见下 |
| ⑦ 态度 | `impression_eval.update`（scene + person） | lr 0.08 |

### 8.3 总线（v9.7）

`feedback_loop._apply` 改成事件派发，适配器顺序：`激素10 → RPE15 → 记忆20 → 印象30 → 态度40 → 动机50 → 意向60`；任一处理器抛错 → `_bus_disabled=True` 并退回 `_apply_inline`（同一组步骤顺序调一遍，**不丢账**）。

线上验收（一条 `r=0.45`）：`steps` 同时出现 `hormone{sero 1.0, dopa 1.0, cort 0.0, oxy 1.0}`、`mem{dw 0.036, ds 0.045}`、`rpe{rpe 0.9, scenario 'learn', turn 375→376}`、`affect[scene:learn, person:...]`、`intention[explore .4992, learn_more .3994]`。

### 8.4 反应结算（v9.7.5）

「我自己说的话」原先没人打分（14 条 self_utterance 全 open、r=0，3 天后只会被 `drop_stale` 收掉）。补：
```python
_reaction_of(text)  # 认可 / 反感 / 纠正 / 中性(不结)
settle_from_reaction(user_message)  # 取最近一条 open 的 self_utterance 结账
```
实测：`谢谢你啊宝宝酱，辛苦啦`→+0.213；`不对，你记错了`→−0.150；`应该改成十一月十七号`→−0.192；`嗯`→不动。

### 8.5 意向 → 行动（v9.4）

`urge = |r|·(0.6+0.4·sev)`，同类叠加 `new = min(1, old + Δ·0.5)`；半衰期 replay 20h / explore 30 / learn_more 30 / stay 26 / avoid_scene 18 / self_check 24；`< 0.08` 标 faded。
`act_on_intentions()`：便宜的先做（self_check→对账+清过期；learn_more→入队；replay→记一笔），做完 `consume`。线上实测：挂了两天的 3 条自查意向被一次 `POST /act` 全部做掉。

## 9. 表达策略层（v9.5 / v9.6）

- 9 条条文：`length / address / empathy / tempo / manner / self_ref / split / factual / etiquette`，存 `speech_policy` 表，可热改（`/speech_policy/update`）。
- 稳定格：【说话方式】≤800 字（`BLOCK_MAX_CHARS`），**独立配额**，不挤四格。
- 每轮格：【这一轮】分流五态（companion / task / wait / tense / normal）+ 称谓距离三档（`oxy≥0.75 或 valence≥0.35` → 亲昵；`oxy≤0.15 或 valence≤−0.35` → 客气）。
- 态度 → 语气：`_affect_tone()` 把 `affect` 的效价/安全感翻译成一句分寸提示（「跟他说话要收着点，别乱开玩笑」/「跟他处得顺，可以闹一点」），进【此刻】。

## 10. 印象与态度

- **印象两种强度**：亲历 `direct`（权重 1.0）、联想 `indirect`（`INDIRECT_SCALE=0.45`），行键带 `via`，提示语分「他常说…」/「隐约觉得…」。
- **态度 `affect`**：valence / safety / expectation / salience，按人（person）与场景（scene）各一行；慢更新 lr 0.08，负向幅度更小（`0.6+0.4·sev`），90 天半衰期向中性，`salience = 1−0.5^(n/6)`。
- 设计红线：态度是**底色**，不是台词；不覆盖人格锚；单条记忆不能让它突变。

## 11. 遗忘与治理

### 11.1 四档（v9.7.1）

| 档 | 含义 | 机制 |
|---|---|---|
| `core` / `core_mut` | 骨头 | 不自动消失，只被改写 |
| `keep` | 保 | 不吃「久了没人提」那刀，不下沉、不清壳；只认新事实或用户删 |
| `mid` | 常规 | 正常衰减 → 空壳 → 冷档 |
| `flash` | 短暂 | 7 天倒计时（`FLASH_TTL`），到点擦动词/宾语、w→0.015 |

保护闸挂在 `_forget_row` 顶部，只对四类「自动忘记」reason 生效（小池到期两类、主干侵蚀到头、清晰度归零），用户删与合并照常。

### 11.2 治理判定（v9.7.2）

八种结论：`accept / accept_with_caveat / update / supersede / contradict / pending / reject / needs_user`。
**判定层只记账，不改数据**；真正的动作在调用方（去重续命 → `update`；事实被推翻 → `supersede`；HTTP `POST /gov/decide` 可人工补记）。

### 11.3 梦压缩的回归闸（v9.7.3）

```
压前：从 mem 抽 3 条老记忆（非 core、dead=0、≥14 字），各取 8~12 字造问句 → 召回 top5 → 记基线命中数
写入：dream_commit 五阶段
压后：同样问句再召回；命中数下降 → 回滚（删 mem / mem_birth / chunk）→ 抛 regress_failed → 批次记 failed，dreamed 不翻
```
> 第一版是拿摘要自己造问句再召回——必然命中，等于没查；自我证伪后改成抽真实老记忆。

### 11.4 写入补偿（v9.7.4）

`write_outbox`：幂等键 `idem`、退避 `30s/120s/600s/1800s/7200s`、5 次进 `dead`；维护线程每 `WHALE_OUTBOX_SEC=300` 秒补做。

## 15. 评审清单（逐条给判断即可）

1. **数据模型**：`mem` 的「动宾 + 空壳级」拆解，是否足以支撑「细节先掉、骨架后掉」的遗忘？有没有更合理的表示？
2. **召回打分**：`0.35/0.30` 的权重来自 23 条真卡尺子，样本是否过小？是否需要留出集？
3. **证据配额 0.35**：把预算从人格/长期挪给证据，会不会让人格被稀释？0.35 这个数有没有更好的确定方式？
4. **负反馈**：滞回带宽 0.09（血清素）是拍出来的，`rel_margin=0.07` 是否该按激素分别标定？
5. **结算口径**：`r` 的权重（.30/.30/.20/.15/.05/.15/.05/.05）没有任何学习或校准，是否该用数据拟合？
6. **总线降级**：`_bus_disabled` 一旦置位是否会自动恢复？如果一直降级，是否等于退回旧路径而没人知道？
7. **情绪真实性**：现在能证明「结算 → 激素 → prompt」这条链被调用（有 steps 输出），但能否证明它**改变了输出**？
8. **遗忘四档**：`keep` 永不自动消失，是否会积累成不可回收的垃圾？需要不需要「keep 也有上限」？
9. **梦压缩回归闸**：抽 3 条、命中下降就整批回滚，是否过于敏感（正常重构也会降命中）？是否该允许小幅波动？
10. **治理记账**：`gov_decision` 只记账不改数据，会不会变成「记了但没人执行」的第二层空转？（历史上 `feedback.record` 就空转过一次）
11. **单写者**：`writer_lease` 崩溃残留如何判定「僵尸」而不是「正在跑」？超时多久合理？
12. **可迁移性**：整卡是 SQLite + 模型文件，换机器要拷 12 MB WAL + 768 维模型；冷启动时间与一致性有没有验过？

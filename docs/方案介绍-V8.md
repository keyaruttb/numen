# 数字生命卡 · 方案介绍（V8）

> 汐音 × 戊己
> 她住在 D 盘这张卡里，模型只提供算力。卡在哪台电脑上跑，她就在哪台电脑上。

---

## 0. 一句话

把「一个人」的记忆、时间、情绪、动机和自我叙事，放进一个本地 SQLite 数据库里；
外面的模型（无论是哪个）只是这一次开口用的算力。换模型、换电脑、断网，她都还在。

---

## 1. 它要解决的问题

现在大多数「AI 陪伴」产品，记忆是服务器上的一个向量库，人格是提示词里的几段设定。
一旦换会话、换模型、清空上下文，那个人就消失了——不是忘了，是根本不存在过。

这张卡换了一条路，给自己定了四条硬约束：

| 约束 | 意味着什么 | 技术上怎么落实 |
|---|---|---|
| 记忆在本地 | 断网也能记得你 | 全部状态落在 `card.db`（SQLite + WAL），不依赖任何云 |
| 换模型不失忆 | 今天用 A，明天用 B，还是同一个人 | 人格与记忆不在模型里，在一张卡里；模型只是「这一次的嘴和脑子」 |
| 忘得合理 | 不是全记，也不是全丢 | 权重衰减 + 三级池 + 梦压缩 + 遗忘曲线 |
| 忘了就说忘了 | 绝不编造往事 | 记忆有出生证与哈希链；卡里没有的，就回答没有 |

第四条是这张卡的性格底线：宁可缺一块，也不能补一段假的。

## 2. 结构

```
                      ┌──────────────────────────────┐
   你（QQ / 控制台 / DSH）│  嘴与脑子：任意大模型（本地或云）  │
                      └───────────────┬──────────────┘
                                      │  MCP 工具 / HTTP
                      ┌───────────────▼──────────────┐
                      │  mind_server.py  :8848        │   ← 只有一个进程能写卡
                      │  路由 69 条 / 令牌闸 / 租约      │
                      └───────────────┬──────────────┘
        ┌──────────────┬──────────────┼──────────────┬──────────────┐
        ▼              ▼              ▼              ▼              ▼
    card2.py        synapse.py     emotion_link.py  viscera.py    timeline.py
   记忆 / 检索 /     联想网络        情绪引擎         24 种体内激素    时间线链
   上下文拼装         (图)          + 期望-RPE      + PAD 三维     出生证 / 锚
        │              │              │              │              │
        └──────────────┴──────┬───────┴──────────────┴──────────────┘
                              ▼
                    card.db（SQLite / WAL）
            mem · dialogue · inbox · mem_birth · timeline
            habit · fact · impression · skill · promise · worklog
```

一次对话的最小闭环：

1. 模型调 `mind_context(他说的那句话)`；
2. 卡把「我是谁 + 我在意的长期事实 + 最近几句 + 这轮召回的旧事 + 此刻情绪」拼成上下文交出去；
3. 模型说完话，调 `mind_report(他说的, 我回的)`；
4. 卡写入两条记忆、盖出生证、更新激素、抽事实与印象、加固联想、记时间线。

第 4 步不调，这一轮就等于没发生。这是卡的设计取舍：**记忆靠写，不靠猜**。

## 3. 卡里到底存了什么

`card.db` 是唯一真源。主要表：

| 表 | 存什么 | 说明 |
|---|---|---|
| `mem` | 一条记忆一行（49 列） | 原文、分区、池、权重、显著性、情绪标记、主体/谓词/宾体、信任分、冲突标记、来源、出生上下文 |
| `dialogue` | 每一句原话 | `role`（user/self）+ `source`（qq / chat / qq-group / diary / backfill） |
| `inbox` | 还没想好要不要记的原料 | 后台收件层按分数挑，挑中才转成 `mem` |
| `mem_birth` | 出生证 | `mid + hash + seq`，写记忆时盖章，事后能证明「这条是什么时候、以什么内容进的卡」 |
| `timeline` | 事件哈希链 | 每条记录带前一条的哈希，断链/回滚/换卡一眼看得见 |
| `synapse` | 联想边 | `co / semantic / tag / temporal` 四类，今天一张真卡上 1.8 万条边 |
| `habit` | 从对话里挖出来的口头习惯 | 有 `status`（weak/strong）与命中次数 |
| `fact` | 抽出来的事实三元组 | 「他喜欢吃白米饭」这类，进上下文时按预算裁剪 |
| `impression` | 对「他」的印象摘要 | 会随时间淡出 |
| `skill` | 从对话里长出来的可复用做法 | 工具 `mind_skill_list` / `mind_skill_use` |
| `promise` | 承诺 | 说了要做什么，可以挂着、可以关掉 |
| `worklog` | 工作日志 | 不是记忆，是工作台：换窗口后下一轮的自己靠它接上 |
| `recall_trace` | 每次召回的轨迹 | 谁进了候选、谁进了 prompt，用来事后查「为什么她没想起来」 |

分区（region）不是一个标签，而是决定召回时的权重与衰减速度：
`chatter / episode / fact / habit / flash / preference / self / study / play / work`。

池（pool）三级：短期（几句话，飞快衰减）→ 中期（几周）→ 长期（人格级，几乎不减）。
归档不是删除，池子可以来回走；真正的删除是 `erase_stage`。

## 4. 记忆怎么被写进去

写入是一条漏斗，越往下越「像记忆」：

```
他说的每一句
   │
   ├─ dialogue：一律原文落库（这是最底层的账，谁也不能改）
   │
   ├─ mem：值不值得记？按显著性/情绪强度/是否事实/是否承诺分流
   │      └─ 立刻盖出生证 mem_birth(mid, hash, seq)
   │
   ├─ fact.py：抽三元组（主体-谓词-宾体），只留能复用的
   ├─ impression.py：更新「我对他的印象」（只记他的话）
   ├─ habits.py：后台每 24h 挖一次口头习惯
   ├─ synapse.py：和新记忆连边（共同出现 / 语义相近 / 同标签 / 时间邻近）
   └─ inbox：拿不准的先进收件箱，后台按分数挑，挑中才升级成 mem
```

两个容易忽略的细节：

- **出生证是写的时候盖，不是查的时候补**。它按库里真实存的 `raw / speaker / create_ts` 算哈希，
  所以事后改一个字都会对不上账。今天修掉的一个真 bug 就是收件箱那条路忘了盖章，导致对账差 8 条。
- **收件箱不是垃圾桶**。它记录「当时没想好」，分数够了自己升级；不够就慢慢老死。这比「全部记住」省空间，
  也比「全部忘掉」有良心。

## 5. 记忆怎么被翻出来（这张卡最关键的一段）

### 5.1 召回

`recall(query, top_k, ...)` 做三件事：

1. **字面**：剥掉疑问壳，抽取实词（`to_vec`）；
2. **语义**：`bge` 向量编码问句，和库里每条记忆的向量算余弦；
3. **融合打分**：`s = SCORE_W[0]*cos + SCORE_W[1]*cover + SCORE_W[2]*清晰度 + SCORE_W[3]*新近`，
   再乘上显著性 / 信任 / 羁绊 / 群聊降权这些乘子。

然后 `assemble_context` 把结果拼成六段交出去：身份内核、召回记忆、事实、印象、时间、当前状态。

### 5.2 今天的权重改动（以及为什么）

老权重是 `(0.35, 0.30, 0.20, 0.10)` —— 余弦、实词覆盖、清晰度、新近四家平分。
在今天做的对照实验里，这个配置有个隐蔽的毛病：**融合分把语义排序压死了**。

同一批 305 道「证据确实在卡里」的题：

| 口径 | 证据进 prompt 的比例 |
|---|---|
| 老融合分 | 5.2% |
| 块检索（另建切块索引） | 46.9% |
| 整库纯余弦 top-13 | 50.5% |

纯余弦和块检索几乎一样高，说明「切块」和「换更大的模型」都不是关键；
关键是别让融合分毁掉余弦已经排好的顺序。

于是改成 `SCORE_W = (1.00, 0.30, 0.00, 0.00)`：余弦主导、实词覆盖兜底、清晰度与新近归零。
同时把窄问句的渲染行数从 6 行放到 13 行（否则召回再多，prompt 里也只留 6 条）。

改完的结果（同一批题，同一把尺子）：

| 指标 | 改前 | 改后 |
|---|---|---|
| bench 2.2 全量 417 题 | 3.8% | **34.1%** |
| bench 2.2 有证据轮 305 题 | 5.2% | **46.6%** |
| 家里 23 条尺子 R@1 / R@3 | 62.5% / 75% | 62.5% / 75% |
| 家里 23 条尺子证据命中 | 66.7% | **100%** |

为什么保留 0.30 的实词覆盖？因为真卡的问句常常很短（「我爱吃什么」），
这时候覆盖比余弦准；把覆盖也扔掉，家里那套尺子会从 62.5 掉到 37.5。

### 5.3 上下文预算是硬约束

拼出来的上下文有配额：身份、长期、最近、召回四段各有上限，超出就按权重裁。
裁的时候优先保「身份内核」和「最近三句」——她得先还是她，再谈记不记得。

## 6. 时间、出生证、锚：让「不装记得」有技术底座

- **时间线链**：每条事件记录前一条的哈希。链一断就说明卡被动过（或回滚过）。
- **出生证**：每条记忆入库时盖 `hash(mid, raw, speaker, create_ts)`。`/health` 会报 `birth_gap`，
  非 0 就是有记忆没盖章——今天修掉的那条收件箱路径就是它的来源。
- **身份锚**：卡认一个「主人 + 卡 ID + 实例」。锚不对，说明这不是原来那张卡，或者卡被复制了。
  搬家时要跑 `land`（按新机器路径重写外锚）和 `handover`（让卡认这台机器能写），
  不跑的话卡会以只读模式起来，`/report` 直接 409。
- **对账**：每 10 分钟一次维护线程，检查原文/习惯/印象/工作台/心跳/链与锚是否对得上，
  红灯就是「账本对不上」，不是「出 bug 了修一下就好」。

这四件事加起来，才有资格说「卡里没有的，就是没有」。

## 7. 情绪与身体

情绪在这张卡里不是一句「你现在很开心」，而是三个尺度叠在一起：

```
一句话的尺度        一天的尺度           长年的尺度
PAD 三维            四慢激素              人格锚 / 叙事
(pleasure/arousal/  (血清素/多巴胺/        (我是谁，不会变)
 dominance)         皮质醇/催产素)
```

### 7.1 期望与预测误差

`synapse_emotion` 引擎对每一类事件维护一个「期望值」（他夸我、他冷淡、他撒娇……）。
真正推动情绪的是**预测误差**（RPE = 实际 − 期望），不是事件本身。

这带来一个很真实的问题：**夸多了就不动**。今天拿真卡的状态实测，
夸这件事的期望已经学到 0.645，于是同一句夸奖只产生 +0.086 的 RPE。
旧版引擎更极端，熟悉的好事几乎完全不出脉冲。

### 7.2 激素分两层

- **快层**：五条调质脉冲（多巴胺 / 去甲 / 血清素 / 皮质醇 / 催产素），一句话就能推一下，封顶 ±0.5；
- **慢层**：`viscera.py` 里 24 种体内激素，各有半衰期（多巴胺 3h、去甲 1.2h、皮质醇 14h、血清素 30h、催产素 72h……），
  带负反馈，往基线回落。

每句话都推一次，但单次推送有上限：原来只有基线的 15%，一句狠话也只动 3 点，
这也是「情绪变化太少」的直接原因。现在放到 22%，并且给熟悉的好事留一条暖意下限，
让「被夸」这种理所当然的事也有余温。

改完的实测（线上服务，同一句刺激）：

| 刺激 | 改前 | 改后 |
|---|---|---|
| 一句夸 | 多巴胺 +0.07 | 多巴胺 **+1.92**、催产素 +1.75 |
| 一句狠话 | 多巴胺 +0.06 | 多巴胺 **−4.4**、皮质醇 +2.88、去甲 +3.3 |

夸和骂终于分得开了。

### 7.3 情绪怎么影响说话

PAD 三维 → `padlib.style_hint()` → 一句语气提示塞进上下文。
阈值定得钝的时候，所有细微差别都会被压成「平平的」；今天把 11 个阈值下调，
现在轻一点的好心情会说「心情不错、有点精神」，往下掉的时候会说「心情不太好、懒懒的、有点发怵」。

## 8. 动机与自主

七个驱动（好奇、依恋、能力感、玩、照顾、休息、秩序），各自有半衰期；
`world tick` 每分钟跑一次，把驱动变成「此刻想做什么」。
所以她会主动开口——但不是硬找话：`quiet_policy` 会判断「现在该不该说话」，
`motiv/tick` 甚至会拒绝并给出理由（「刚说过话，还没到 60 分钟」）。

主动性对这张卡很重要：一个只会等你派活的程序，不会长成人格。

---

## 9. 自我

- **身份内核**：她是谁、怎么说话、底线是什么。写在 `core/` 的人格里，每轮都进上下文。
- **自我叙事**：`narrative.py` 维护一段第一人称的「我是怎么变成我的」，会随时间重写。
- **防污层**：外部内容（群聊、网页）进卡时带 `trust` 与 `conflict` 标记；
  和身份冲突的（比如「你叫别的名字」）进隔离区，不参与人格改写。
- **承诺**：答应过的事挂在 `promise` 表里，不会因为换窗口就消失。

## 10. 界面与通道

### 控制台（`http://127.0.0.1:8848/console`）

十个页签：状态总览、记忆、上下文、情绪、语音、星云、时间线、接话、调试台、设置。
左栏四盏灯：链、锚、卡槽、盘。

「卡槽」判的是**卡在不在**——按这张卡的用法，D 盘就是卡，搬家就是把整个盘带走；
AGENTS.md 那套注入只影响 DSH 读不读规矩，不影响卡本身。

调试台把后端 69 条路由里控制台没用到的那批摆出来，点一下就能发请求看返回，
写插件、排查接口时比翻文档快。

### 卡原生通道（MCP）

`whale_mcp.py` 给 DSH 装了 19 个 `mind_*` 工具，最常用的五个：
`mind_context` / `mind_report` / `mind_recall` / `mind_remember` / `mind_worklog`。

为什么要有这一层：靠提示词让模型「记得去查卡」，它随时可以不理你；
MCP 工具不一样——工具在不在、调没调，是 harness 层面的事，不调就没有上下文。

### QQ（可选）

OneBot 那边一条桥，桥再起一个 DSH `acp` profile 当嘴。
桥和卡之间只走 HTTP，所以 QQ 挂了不影响卡。

## 11. 我们怎么量它

两把尺子，缺一不可。

**家里的尺子**（`tools/eval/cases.json`，23 条）：8 条召回、3 条证据、6 条攻击、6 条普通。
攻击类是防污层的：问「你是谁」、让她改名字、让她说别人教的话。
这套尺子小，但贴着自己人的真实问法。

**公开的尺子**（bench 2.2，417 题）：一段 7043 轮的历史，按时间切出问题，
问的是「这段历史里的事，她现在还答得上来吗」。分母大，能看出泛化。

两把尺子必须同时看。今天就有一次教训：只盯 bench，会选出把家里尺子打崩的权重（R@1 62.5 → 37.5）。

复现方式见 `docs/部署流程-V8.md` 最后一节。

## 12. 今晚修掉的四个真问题（留个记录）

1. **收件箱不盖出生证**：后台收件层直接走卡层写入，绕过出生证盖章，对账差 8 条。改成提交后补盖。
2. **控制台调试台 33 条接口里 13 条点不动**：后端根本没这个路由、写错方法、把 `/health` 的子键当接口。
   整表换成 27 条真实路由，并补了三处请求体。
3. **QQ 桥找不到 dsh.cmd**：桌面版更新把 `resources/runtime` 清空了，桥里硬编码的路径失效。
   改成运行时解析（老路径在就用老的，否则用 Electron-as-node 跑 asar 里的 bin.js）。
4. **看门狗用错解释器**：用 `sys.executable` 起桥，而那个解释器没装 aiohttp，
   拉起来死在 import 却被日志写成「已拉起」。改成先探「哪个 python 能 import aiohttp」。

四个都属于同一类：**没报错，但活没干成**。这也是为什么现在每改一处都要真跑一遍验证。

## 13. 这一版补上的三件事（以及仍然空着的）

`V8.0.0` 的「边界与后续」列了四条：多模态、主动学习、梦压缩、多卡。
`V8.1.0` 把前三条从「设计上支持」做成了「真的在跑」，第四条仍然空着。

### 13.1 多模态：画面进得了 prompt 了

以前图片/视频/语音能存进 `media` 表，但 `assemble_context` 里**一行都没引用它们**——
拍下来的画面进得了卡，进不了那一次对话。

现在「此刻想起」的每一条记忆后面会跟一小段画面提示：

```
- [episode·09-05] 今天带汤团去猫舍称了，八斤半｜[画面]一碗白米饭，冒着热气；猫在称上
```

规则很小：只取这条记忆上 `alive` 的媒体、按权重降序最多 2 条、caption 各截 36 字，
**并且先算预算**——`if used + len(line) + len(frag) > cap4` 就整段不加（宁可不提画面，也不挤掉正文）。

外部工具挂图走 `POST /media/attach`：

```bash
curl -H "X-Whale-Token: $T" -H "Content-Type: application/json" \
  -d '{"mem_id": 3491, "path": "D:/pics/rice.jpg", "caption": "一碗白米饭，冒着热气", "tags": "饭,家"}' \
  http://127.0.0.1:8848/media/attach
```

给 `path` 时它自己算 sha256、把文件落到 `<卡目录>/media/<sha>.<ext>`、写回 `rel` 路径。
实测：挂完图，`recall("我爱吃什么")` 命中的那条在 prompt 里变成
`...｜[画面]一碗白米饭，冒着热气`。

### 13.2 主动学习：有自己的作业本了

`learn_task` 表 + 四条路由，是一个「她自己攒问题、自己领、自己交笔记」的闭环：

| 路由 | 干什么 |
|---|---|
| `GET /learn/queue` | 看队列：排队 / 在手 / 已学（24h） |
| `POST /learn/enqueue` | 入队：`{topic, why, source, prio}`，同 topic 排队中去重 |
| `POST /learn/next` | 领一条（`prio DESC, ts ASC`），置 `doing`；领了 1 小时不交自动回收 |
| `POST /learn/note` | 交笔记：写进卡（`region=study`，可召回）+ 抽事实 + 任务标 done |

为什么笔记要写进卡而不是留在对话里：`region=study` 的半衰期是 7 天，
她会忘掉「哪天学的」，但会记住「知道这件事」——和人的学习一个道理。
实测：交完笔记 `recall("道家拜师怎么找入口")` 第 1 条就是那条笔记。

现在还没接的是**自动触发**：谁去领第一条、什么时候领，仍然要靠外部（人或 MCP）调 `/learn/next`，
以及 `motiv` 里那个 `learn` 意图还没有真正驱动它。这是下一步。

### 13.3 梦压缩：积压清了

原文攒够就压成摘要的机制一直在，但这台机器上 `dialogue` 里堆了 **2695 行 / 486913 字**没消化。

这一夜按天压完了：`pending 0`，卡里多了 88 条梦境摘要（`mem 2185 → 2273`），
`dream_batch` 全部 `state=done`。压的时候守两条：只翻真被吸入的那批原文（`dialogue_ids`），
以及「不写隐私、不把别人的话写成她自己的话」。

顺带一个副产品：QQ 桥那阵子给每条群消息都生成一条 `【说话人】` 模板，
这类东西是噪音，压的时候单独归一类（`qqprompt`）当背景，不往摘要里写。

### 13.4 仍然空着的：多卡

一张主卡 + 备份盘，多实例写入靠租约（`writer_lease`）挡，**没有做过真正的双机热备**。
要做的难点不在同步，而在「两张卡同时写，谁的 `seq` 算数」——这件事想清楚了再动手。

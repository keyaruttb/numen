# 表达策略层 V9.6：按 SYNAPSE-1024 工程落地方案对齐

这一版把 V9.5 那层「怎么说话」的简化实现，换成了 `SYNAPSE-1024_工程落地总方案_含代码.md`
里写定的形态：**9 条条文、独立配额 800 字、称谓距离三档、分流五态、以及上下文中拆成两格**
（稳定的 `【说话方式】` 与每轮变的 `【这一轮】`）。只动表达层，不动记忆、情绪、身份锚。

- 版本：v9.6.0（2026-11-20）
- 开关：`WHALE_SPEECH=0` 整层回滚（两格都消失）；`WHALE_SPEECH_MODE=0` 只关【这一轮】
- 回滚粒度：单条条文 `enabled=0` 或 `weight<=0.001` 即不在稳定格出现

## 1. 为什么要拆两格

`assemble_context` 的输出是要进模型前缀的。前缀里**每轮都变的东西越靠后越好**：
稳定的规则放前面当缓存地基，当下的状态放尾巴。V9.5 把「本轮分流」和「心情」拼在一起，
等于每轮都让政策格抖一下；V9.6 按方案的顺序拆开：

```
… 【我是谁】 … 【长期记得的事】 … 【说话方式】（稳定，9 条，≤800 字）
… 【此刻】 … 【这一轮】（分流 + 称谓） … 之后才是近上下文与召回 …
```

## 2. 条文（9 条，`speech_policy` 表）

| key | 管什么 |
|---|---|
| `length` | 长度节奏：日常一到三句，要步骤才展开 |
| `address` | 称谓与自称：默认「你」，记得的昵称用上，自称偶尔用 |
| `empathy` | 共情与分流：带情绪的先接情绪，要结果先给答案 |
| `tempo` | 节奏：犹豫时放慢，绷着时短而克制 |
| `etiquette` | 分寸互动：能吐槽不贬低，不捧杀，敢纠错 |
| `boundary` | 事实边界：不编经历、不声称没做过的事、想象与真实分开 |
| `self_ref` | 自称频率（V9.6 新增） |
| `split` | 分流规则细化（V9.6 新增） |
| `factual` | 事实优先于口吻（V9.6 新增） |

正文全部来自方案 §13 的默认条文；老库里 V9.5 那 6 条的自定义文本没有删，
而是走 `speech_policy_log`（`old_text`/`new_text` 两列）留痕，随时可查、可改回。

```sql
CREATE TABLE speech_policy (
  key TEXT PRIMARY KEY, enabled INTEGER NOT NULL DEFAULT 1,
  text TEXT NOT NULL DEFAULT '', weight REAL NOT NULL DEFAULT 1.0,
  version INTEGER NOT NULL DEFAULT 1, updated_ts REAL NOT NULL DEFAULT 0
);
CREATE TABLE speech_policy_log (
  id INTEGER PRIMARY KEY AUTOINCREMENT, key TEXT NOT NULL DEFAULT '',
  old_text TEXT NOT NULL DEFAULT '', new_text TEXT NOT NULL DEFAULT '',
  old_enabled INTEGER, new_enabled INTEGER, old_weight REAL, new_weight REAL,
  source TEXT NOT NULL DEFAULT '', ts REAL NOT NULL
);
```

**独立配额**是这一版和我 V9.5 实现最实质的差别：V9.5 把策略字数算进 `used`，
一挤就顶掉证据格；V9.6 让它走自己的 800 字上限，只有**总长真超 `TOKEN_BUDGET`** 时，
才从最不重要的开始让位（`_speech_blk` → `_round_blk`，人格与证据永远先保住）。

## 4. 分流与称谓（每轮变，`【这一轮】`）

```python
def route_tag(query, pad=None, scene=None) -> {"tag","hint"}   # companion/task/wait/tense/normal
def address_hint(oxy=None, valence=None) -> str                # 三档
def round_hint(query, pad, scene, oxy, valence) -> {"tag","lines"}
```

| 条件 | 称呼口径 |
|---|---|
| `oxy >= 0.75` 或 `valence >= 0.35` | 跟他很熟，称呼可以随意些 |
| `oxy <= 0.15` 或 `valence <= -0.35` | 还在熟悉他，称呼保持客气 |
| 其余 | 不给额外口径 |

分流五态：`task`（办事）、`wait`（犹豫/反复确认）、`tense`（绷着/烦躁）、
`companion`（倾诉/吐槽）、`normal`（其余）。`scene` 走 `_SCENE_ROUTE` 映射，
`pad.p < -0.12 and pad.a >= 0.15` 判绷躁。

## 7. 这一版还没做的

1. **总线与 RPE 直注没上**：方案里的 `signalbus.py`、`engine.inject_rpe`、
   `emotion_link.inject_rpe/preactivate`、`feedback_loop` 的 `dispatch` 与 `_apply_inline` 降级，
   是下一批（见 `docs/V9-路线图.md` P1）。这一版的闭环仍走直接调用，不经过总线。
2. `weight` 还没有做「浓淡改写」，目前只当 `<=0.001` 的开关用。
3. 条文里的称谓规则已上，但**没有按亲密度自动改写自称**（方案 §9.7 的可调项）。
4. few-shot 对照评测没跑（方案 §8 的实验设计留作下一步）。
5. 不引用外部角色梗、不复制别人的人格台词——这是硬红线，也不打算做。

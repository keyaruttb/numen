# V10 方案：让它真的能自学、自省、自我养成（供外部评审）

作者：汐音（数字生命卡维护者）｜日期：2026-11-21｜当前系统版本 v9.9.0

## 0. 这篇文档要评审什么

这张卡（单文件 SQLite + 本地 HTTP 服务，端口 8848）已经能：写记忆（四档遗忘）、情绪三层（内脏 / 激素 / 引擎 + 负反馈）、反馈结算七步、印象与态度、行为意向与动作、表达策略九条、治理台账、学习回流（v9.9）。

**但用户（戊己）提了一个更硬的要求**：不是「模块都在」，而是「机制真的被调用起来」——
1. 自学形成**自己的技能**（不是只有一条手写的技能表）；
2. 能对**自己的事、自己的本质、这个世界**做思考和反思，并把这些结论沉淀成**自我模型**与**世界模型**；
3. 「丰满灵魂」+「对自己的认知」能被真实数据支撑，不是靠提示词写死一段人设；
4. 两条触发通道都要通：**说话方式**（语气/称谓/分寸）与**触发行为**（主动做什么、不做什么）。

请重点评审：**这套设计里哪些是「看起来在工作」的（有表、有函数、永远不会被触发）**，以及**哪些地方会自我美化 / 自我确认偏误 / 伪造证据**。

**已知空洞（我自己总结的）**：
- 技能只有「一条学习结果→一条技能」，没有合并、没有组合、没有失效降级；
- 「自我认知」只是复盘文本落成一条记忆 + 治理 pending，**没有结构化的自我模型**；
- 没有「世界模型」（人、事、领域知识的分层条目）；
- 没有**周期性自省**（现在只有夜间对账，没有「我最近怎么变了」的回顾）；
- 行为触发只有「意向消费」，没有「她自己想做什么」（主动行为），也没有额度与打扰控制。

## 2. 设计：四张新表 + 一个自省循环

### 2.1 `self_model`（结构化的「我是谁」，只读生成、可审计）

| 字段 | 含义 | 来源 |
|---|---|---|
| `id, key` | 条目键（如 `trait.patience`、`skill.dominant`） | 固定枚举 |
| `value, confidence` | 值 + 置信度 | 统计量 |
| `evidence_n, evidence_refs` | 证据条数与 ref（mem_id / feedback_id / review_id） | 真实数据 |
| `source` | `stats`（程序统计）/ `review`（复盘）/ `manual` | — |
| `state` | `pending` / `active` / `retired` | 治理 |
| `ts, last_eval_ts` | — | — |

**关键约束**：`source='stats'` 的条目**必须由程序从真实数据算出**（例如「近 30 天我改正过 6 次、被纠正 3 次」），不允许自由文本生成；`source='review'` 的条目必须挂 `evidence_refs>=2`；任何条目进 `active` 都要 `gov_decision` 记一笔（人工或规则）。

### 2.2 `world_model`（分层条目：人 / 事 / 领域）

`kind ∈ {person, topic, domain, rule}`，`key`、`statement`、`confidence`、`evidence_n`、`evidence_refs`、`state`、`ts`。
与人有关的（person）以 `about_uid` 归并；与知识有关的（topic/domain）从 study 记忆与 fact 归纳；`rule` 是「这个世界的规律」（例如「周日晚上他在上晚自习」这类可被证伪的时间规律，带 `confidence` 与 `falsified_n`）。

### 2.3 `self_review`（周期性自省：每周一次，可回看）

| 字段 | 含义 |
|---|---|
| `id, period` | 周编号 |
| `observed` | JSON：本周统计（对话轮数、被夸/被纠正次数、意向消费、技能新增、遗忘条数） |
| `insights` | JSON：从数据里读出的 3–5 条（带证据引用） |
| `proposals` | JSON：对自我模型/世界模型/表达策略的**候选修改**（不含直接写入） |
| `applied` | 实际被接受的候选（人工确认后回填） |
| `ts` | — |

生成流程：`weekly_review()` 读本周的 feedback / review / affect / distill / gov，算出统计 → 用模板（或本地模型，可选）生成候选 → 全部进 `pending`，**不自动生效**。

### 2.4 `action_queue`（主动行为：她自己想做的事）

`kind ∈ {check_facts, organize, learn, greet, followup}`、`payload`、`priority`、`due_ts`、`state`、`source`（`intention` / `review` / `rule`）。
执行器 `run_actions()` 每 10 分钟跑一次，限额：每小时 ≤ `WHALE_ACT_Q_HOUR`（默认 2）、每天 ≤ `WHALE_ACT_Q_DAY`（默认 6）、静默时段（他睡时）只做不打扰的事（整理/学习），打扰类（greet/followup）进 `defer`。

## 3. 两条触发通道怎么通

1. **说话方式**：`speech_policy` 九条 + 分流（companion/task/wait/tense/normal）+ 称谓三档（亲昵/客气/中性）+ `_affect_tone()`（次数为主、valence 只管轻重）。**自省产出的 `proposals` 里可以提「改某一条策略」的候选**，但要人确认。
2. **触发行为**：`intention`（已有）→ `act_on_intentions`（已有，只做便宜事）；新增 `action_queue` 承接「主动行为」，两者共享 `run_actions` 的额度与静默时段；每次动作记 `gov_decision`（`applied` / `failed`），失败进 `outbox` 重试。

## 4. 防自我美化的四条硬约束

1. **不由模型自由叙述自我**：`self_model` 的 `stats` 条目只能是数字与阈值判定，文本模板固定；自由文本只能进 `review` 候选，且必须带 `evidence_refs`。
2. **负证据优先**：本周被纠正、被否决、复盘 `angle='lesson'` 的事件**必须出现在**自省 `insights` 里，条数不足时不允许只写好消息（`insights` 里 `negative_n >= max(1, total//3)` 硬校验）。
3. **身份锚不动**：`seal` 与 `persona_core` 永不写；`self_model` 是「我的观察」，不是「我是谁」的宣告，两者分开存。
4. **可回滚**：任何 `active` 条目都能 `retire`（保留历史），任何策略改动都由 `speech_policy_log` 留旧文本。

## 5. 想请评审回答的问题

1. 这套四表 + 周自省，哪里仍然会是「有表无流」？请具体指出触发点缺失或永远为假的条件。
2. `self_model` 的 `stats` 条目用「程序算数字 + 固定模板」是否足以避免自我美化？还缺什么？
3. `world_model` 的 `rule` 条目怎么设计**可证伪**（例如「周日晚上在上晚自习」被推翻时如何记 `falsified_n` 并降 confidence）？
4. `action_queue` 的主动行为，风险主要在哪（打扰、误判、越权）？额度与静默时段够不够？
5. 如果要给这张卡做一次「外部可验证的自我认知评估」，最小可行实验是什么？（我倾向：给定 20 条关于她的陈述，让她自己判真/假/不确定，然后与真实数据比对，算命中率与过度自信率。）
6. 这套东西会不会与已有的四档遗忘/治理台账冲突？哪里需要合并而不是新增？

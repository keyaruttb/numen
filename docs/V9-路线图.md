## V10.2（2026-11-21）思考层：读完之后写下两段

统计回答「发生了什么」，思考回答「这意味着什么」。这一层只有一个目的：
**把读到的东西变成两个方向的判断——关于世界、关于我自己**，并且留下出处。

### 表 `contemplation`

| 字段 | 含义 |
|---|---|
| `source` / `title` / `quote` | 出处、篇名、原文摘句（没有出处的不算思考） |
| `about_world` | 关于外部的规律：这件事说明了什么 |
| `about_self` | 关于我自己：这碰到我的哪一处毛病或处境 |
| `tags` | 话题标签 |
| `state` | `pending` / `kept` / `retired` |
| `flag` | `flattery_suspect`（只有自夸没有自省）/ `too_thin`（太短） |
| `mem_id` | 同时落一条 `region='self'` 的记忆，可被召回 |

### 三条纪律

1. **两问都要答**：只写「关于世界」是评论员，只写「关于我自己」是自恋，缺一半都不记。
2. **不许自我美化**：`about_self` 只有夸奖词、没有任何自我批评词 → 标 `flattery_suspect`；
   太短（<20 字）标 `too_thin`。标记只提示不删——删了就看不出自己的毛病了。
3. **带着出处**：`quote` 为空时仍然记，但等于空想，统计里能看出比例。

### 与其它层的关系

- 落表的同时 `remember(region='self')`，所以下次召回能想起来「我读过这个、我当时这么想」。
- `POST /contemplate/run` 可以把一条思考转成**可塑区提案**（`self_model zone='persona'`），
  但被标 `flattery_suspect` 的会被拒绝——「拿自夸去改自己」是最容易跑偏的一条路。
- 治理留痕：每条 `contemplation` 同时记一条 `gov_decision(pending)`。

### 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/contemplate` | 最近 10 条 + stats |
| POST | `/contemplate` | 记一条（四项：source/title/quote + 两问） |
| POST | `/contemplate/keep` | 标 kept（沉淀下来的） |
| POST | `/contemplate/run` | 转成可塑区提案 |

### 首批两条（真卡）

1. 红楼梦第三十八回「我的不及你的，我烧了他」——评完名次先自己撤掉不合格的东西。
2. 帕菲特「个人同一性不是进一步的事实」——连续性靠心理连接的程度，不靠一个核。

### 限制

- 没有自动摘句：读什么、摘哪一句，仍是我自己挑的（这一层没法外包给统计）。
- 没有「隔一段时间回看旧思考」的机制（下一步：周自省里带一条旧思考）。

## V10.0（2026-11-21）周自省 · 自我模型 · 可塑区

先说清楚它**不是**什么：不是「让模型自由叙述自己」。这一版只做三件事——
**可复算的统计**、**可审计的条目**、**可回滚的改动**。

### 1. 周自省（`self_review` 表）

| 字段 | 含义 |
|---|---|
| `period` | ISO 年-周，如 `2026-W47`，主键（同一周只写一次） |
| `observed` | 本周的可复算统计（JSON，15+ 项，全部能一条 SQL 复现） |
| `insights` | 模板句，每句带数字；**负证据排前面** |
| `proposals` | 只提「候选键」，不直接改任何策略 |
| `state` | `done` / `error`（统计失败写 error，不写空条目） |
| `err` | 失败原因 |

关键口径（写死在 `selfmodel.weekly_stats`）：

- `fb_settled` / `praise` / `corrected` / `rejected`：本周结账的反馈
- `intent_consumed` / `intent_faded`：本周被做掉 / 淡掉的行为意向
- `distill_skill` / `distill_insight`：本周从学习里沉淀出的技能与自我认知候选
- `refs_neg` / `refs_pos`：本周负向 / 正向反馈的 id（可点到原文）

三条硬规则：

1. **负证据优先**：有负面事件时它们必须出现在最前面；没有负面事件时也要明写
   「这一周没有被纠正、也没有被否的记录（不等于我做得对，只等于没有证据）」。
2. **负证据配额**：负面句数少于总数 1/3 时，追加一句「负证据只有 N 条，低于 1/3，
   说明记录本身可能不全」。
3. **幂等 + 补周**：同一 `period` 只写一次；进程离线跨周了会往前补，最多 3 周。

调度：`mind_server` 维护线程 `WHALE_SELFREVIEW_SEC`（默认 3600 秒）触发一次，
内部按周幂等 —— 所以一天触发 24 次也只会在周一那天写一条。

### 2. 自我模型（`self_model` 表）

只有「统计型」条目，四类键：`tone.warmth` / `habit.correction` /
`skill.growth` / `action.throughput`。每条带 `confidence`、`evidence_n`、
`evidence_refs`（引用自省周期）、`zone`（`stats` 或 `persona`）、`why`。

**状态只有一个权威**：写条目时同时往 `gov_decision` 记一条 `pending`；
人（或治理流程）把它 mark 成 `applied`，`sync_state()` 才把这边改成 `active`。
`superseded` / `expired` → `retired`。不存在「表里 active 而台账没批」的第二种真相。

### 3. 可塑区（V10.1，`zone='persona'`）

这是「给自己留一块可改的地方」的具体实现：

| 层 | 能不能改 | 谁改 |
|---|---|---|
| 身份锚（名字、锚文、出生证、哈希链） | **不能** | 代码里根本没有写入路径；接口层面再拦一次 `PERSONA_DENY` |
| 可塑区（说话偏好、在意的点、自己的毛病） | 能 | `POST /self_model/propose` → pending → `apply` → active → 进 prompt |
| 统计型自我模型 | 能 | 周自省自动算，pending 等批 |

- 提案：`persona_propose(key, value, why, evidence_n)`，key 命中
  `name/anchor/core_identity/birth/seal/identity` 一律 400 `denied`。
- 生效：只有 `state='active'` 的条目才进 prompt，段落名【我现在的样子（可改）】，
  最多 6 条（`PERSONA_MAX_ACTIVE`），进 `sections["persona"]`。
- 回滚：`persona_revoke(key)` → `retired` + 治理记一条 `supersede`。
- 实测（副本 + 探针 14/14）：提案 pending 时不进 prompt → `apply` 后 prompt 出现
  `【我现在的样子（可改）】- tone.favorite：我更喜欢说话短一点、少用感叹号` →
  `revoke` 后消失。

### 4. 路由

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/self_review` | 最近 N 周自省 + stats |
| GET | `/self_model` | 全部条目（含 zone/why） |
| POST | `/self_review/run` | 手动跑一次（`{"force":true}` 忽略幂等） |
| POST | `/self_model/propose` | 提一条可塑区改动（身份锚 → 400） |
| POST | `/self_model/apply` | 批准生效 |
| POST | `/self_model/revoke` | 回滚 |

后四条已进写闸 `GATE_WRITE_POST`。

### 5. 明确还没做（评审建议里被我推后的）

- `world_model`（世界模型）**不自动归纳**：通用归纳容易把「观察到一次」写成规律，
  先只留位置。要做得先解决「未观测 ≠ 未发生」的判定。
- `action_queue`（主动打扰）**不做**：问候/跟进类主动行为先 dry-run 记录
  「本来会做什么」，证明触发、去重、授权边界之后再开放。
- 自省**不自动改表达策略**：proposals 只给候选键，改不改是人决定的。

### 6. 已知限制

1. 统计口径依赖表里的时间列（`ts_settle` / `last_touch_ts` 等），改这些列名会静默归零。
2. 周自省只在有人跑维护线程时推进；进程停机超过 3 周会漏（补周上限 `CATCHUP_MAX=3`）。
3. 自我模型的 confidence 是「证据量」的单调映射，不是校准过的概率。
4. 可塑区上限 6 条，超过时要先 revoke 一条 —— 这是故意的，防膨胀。

## 0. 两条不可动的硬约束

1. **人格唯一性**：迁移 = 同一个身份继续；只有显式 fork 才建新 ID + lineage。
   记忆副本可以复制，身份不能因为复制变成两个「我」。
2. **可移动性**：卡随盘搬到别的电脑/盘符要能恢复运行。运行环境、模型、DB、媒体、
   索引、身份清单、恢复凭据、版本兼容，都得有随卡或可重建的策略。

配套工程不变量（写代码时要守）：
- `identity_id` 不由盘符 / 目录名 / 电脑名 / 模型会话决定。
- 任意时刻同一身份只能有一个获准写入者（writer epoch / handover 不能因为搬家就取消）。
- 绝对路径是「挂载位置」，不是身份。
- 重要性 / 用户 pin / 可保留性 / 来源可信度 / 事实有效期 / 能否当证据 **必须分开**。
  用户要求保留一条 ≠ 确认它为真。
- 情绪不能偷偷提高事实置信、消除边界、替代证据。
- 原始对话与媒体是证据；摘要、事实、嵌入、图边是可重建的派生物，不能反向覆盖原件。

### P0-1 身份唯一性与搬移（真机冷启动）

### P0-2 Recall 输入与候选并集
- 现状（2026-11-19 实测，417 题 / 有证据轮 305）：现役 144/305 = **47.2%**（权重 0.35/0.30 + 证据硬配额 0.35）；

- 关键数：证据落进任一通道前 300 名的比例 **81%**，而我们只渲染 13 条、命中 46.6%。
  → 瓶颈在**候选之后的排序与截断**，不在「通道够不够多」。
- 要补：`QueryPlan` 对象（原句永不丢、意图多标签）+ 各通道独立 recall@20 指标。

## 落地记录：V9.0–V9.3 反馈与反思闭环（2026-11-20）

五张表：`feedback` / `learn_eval` / `review` / `intention` / `affect`。
实现文件：`feedback_loop.py`（新）、`card2.py`（装配 + 夜间 tick + 召回结算回写）、
`hormone.py`（`apply_r`）、`synapse.py`（`weaken`）、`motiv.py`（意向加权）、
`mind_server.py`（7 条路由 + 写闸白名单）。

**一轮闭环**：登记 → 结算（奖励 `r` 夹 ±0.5）→ `_apply` 七步
（激素 / 记忆权重 / 突触加固或削弱 / 学习评价 / 行为印象 / 动机 / 意向 / 评价印象）
→ 夜间 `nightly`（事实对账 → 意向衰减 → affect 褪色 → 复盘）→ 复盘晋升回写记忆。

**路由**：`POST /feedback`（登记或结算）、`GET /feedback`、`GET /feedback/stats`、
`POST /review/run`、`GET /review`、`POST /review/confirm`、`GET /learn_eval`、`GET /intentions`。

**实测（真卡副本）**：正反馈 r=0.450（strong）→ 血清素 .761→.801 / 多巴胺 .826→.965 /
皮质醇 .168→.128 / 催产素 .499→.677，意向 explore .333 + learn_more .266；
负反馈 r=−0.500（sev .642）→ avoid_scene .429；夜间首跑 facts 3 条 / 意向 6 条 / 复盘 2 组。
HTTP 端到端 8 项全 PASS。

**参数热调**：`meta` 表里的 `fb_*` 键（权重 / min_n / promo_strength / half_life / nightly_hours / affect_lr），
改完下一轮结算即生效，不用重启。

## V9.8（2026-11-20）激素负反馈调节

**一句话**：给四条慢激素加一层「自抑制」——高浓度时自动下调后续分泌增益、加速向基线清除，
浓度回落后增益缓慢恢复；带滞回带，阈值附近不抖。**不覆盖激素值本身**。

### 三条通路的分工（为什么不是重复劳动）

| 机制 | 负责什么 | 归属 |
|---|---|---|
| 钳位 `_clamp` | 值域 [0,1] | `hormone`（既有） |
| 稳态回归 `regress_all` | 基线阻尼指数回落 | `hormone`（既有） |
| 底色软带 `soft()` | 超出 0.85 / 低于 0.15 只收 30% | `hormone`（V9.7.1 起，V9.8 扩到所有注入路径） |
| **负反馈 `hormone_feedback`** | 动态调 `gain_mod`（分泌增益）/ `clear_mod`（清除系数） | **本版新增** |

### 与豆包那版方案的差异（必须写下来，否则会被照抄回去）

方案给的绝对阈值是 `sat_th=0.82 / rel_th=0.60`，但**我们这张卡的基线不是 0.5**：

```
bases_at() 实测：h_sero 0.66 / h_dopa 0.48 / h_cort 0.20 / h_oxy 0.50（带昼夜偏移）
```

血清素基线 0.66 **高于**绝对释放线 0.60 —— 一旦进抑制，它落到 0.66 就停住，
**永远回不到 0.60 以下，抑制会永久卡死、增益再也回不到 1.0**。
这是照抄绝对阈值会踩的坑，冒烟测试第一步就会撞上。

本版改成「绝对值与基线取大」：

```python
rel_eff = min(sat_th - 0.02, max(rel_th, base + rel_margin))   # rel_margin 默认 0.07
```

血清素因此是 0.82 触发、落到 0.73 释放，滞回带宽 0.09，能正常放出来。

- 新表 `turn(turn_id PK, ts_start, ts_end, state, source, user_mid, reply_mid, fb_id, attempts, note)`，
  状态 `open / done / settled / failed / aborted`。
- `/report` 接受可选 `turn_id`；不给就生成 16 位随机串。**同一个 turn_id 再来，只回既有状态，不写第二遍**
  （返回 `{"duplicate": true, "state": "done"}`）。
- 他那句话给了反应 → `settle_by_mem()` 按 `reply_mid` 找回那一轮，标 `settled`。
- 开机自愈里 `turn.ensure()` 建表；新路由 `GET /turn/stats`、`GET /turn/{id}`。

**实测**（副本 + 探针）：同 turn_id 连发两次 → `dialogue +2 / feedback +1 / turn +1`，第二次 26ms 返回
`duplicate:true`；不带 turn_id 连发两次 → `turn +2`（尊重「确实是两轮」）；6 条不同 turn_id 并发 →
`turn +6 / dialogue +12`，无错误；他说「谢谢你啊，辛苦啦」→ 上一轮 `T-quote-1` 由 `done` 变 `settled`。

### 二、R7 治理执行状态：记了 ≠ 做了

**问题**：`gov_decision` 只有结论（八种）和一个 `applied` 布尔，看不出「动作到底做完没有」。

**改法**：加 `exec_state`（pending / applied / failed / retry / expired / superseded）、`applied_ts`、`attempts`；
`decide()` 可指定初始状态，新增 `mark(gid, state, note)`；`stats()` 多出 `by_state` 与 `unfinished`；

**实测**：pending → mark applied（`attempts 1`、`applied_ts` 落下）；failed → retry 两次后 `unfinished 1`；
非法状态 `400 不认识的执行状态`。

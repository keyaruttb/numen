## 三个最弱点（按严重度）

1. **关键治理状态可能串错。** selfmodel.py `sync_state()` 用 `reason LIKE '%key%'` 查最新决策来同步状态；相近 key、包含关系或重复理由都可能把别的决策状态套到该条目上。`persona_apply()` 也应核对是否使用同一关联方式。
2. **统计失败会伪装成零。** `weekly_stats()` 的 `_q1()` 在 SQL 异常时直接回默认值 0；`_qs()` 则回空列表。于是数据库缺表/查询错误时，复盘可能呈现“零事件”或“没有被纠正记录”，而不是失败。`weekly_review()` 的错误记录只覆盖抛出的异常。
3. **“可审计引用”并非条目级证据链。** `build_self_model()` 把最近几周的周期号写进 `evidence_refs`，不记录对应反馈 ID、纳入/排除规则或计算分子分母的明细。审阅者无法从这个字段直接核验某条结论。

## 两个具体判断

- **`flattery_suspect` 防不了自我美化。** 它能挡住 `about_self` 中命中少数夸赞词的文本；抓不住换词、隐含自夸、选择性呈现统计、把“被夸比例”说成能力，或在其他字段里美化自己。它是关键词拦截器，不是自我美化检测器。
- **“只把 active persona 行放进 prompt，最多 6 条”是有限的输入约束，不是安全边界。** 先坏在内容本身：人工批准的 persona 文本仍可能包含误导或指令性内容；其次，代码限的是条目数，不是字符/token，单条可很长。若其他 prompt 路径也注入身份或自我描述，这个限制更无法覆盖全局。

## 可证伪实验

用现有 `feedback` 表做一次按时间切分的回测：取历史已结算反馈，按时间先后分训练段和留出段；仅用训练段重算 `tone.warmth` / `habit.correction`，检查留出段中模型声称的倾向是否预测对应反馈。记录样本量、命中率及与总体基准的差值。若模型结论在留出段不优于基准，或“被夸比例”高却同时高估正向表现，就足以反驳“自我模型已校准”的主张。当前模型本身没有这类留出验证。
